# Mental Models

## Overview

Use a latticework of mental models from multiple disciplines to analyze problems. Instead of relying on a single framework, apply several models to get a more complete picture. Based on Charlie Munger's approach: "You've got to have models in your head. And you've got to array your experience — both vicarious and direct — on this latticework of models."


## Define Done

- [ ] Strategic situation assessed with evidence from multiple sources
- [ ] Key forces and dynamics identified and prioritized
- [ ] Recommendations account for constraints and trade-offs
- [ ] Action plan has clear owners and timelines

## Instructions

### Step 1: Define the Problem Clearly

Before applying models, articulate what you're trying to understand:

```markdown
## Problem Statement

**Situation:** [What is happening]
**Decision:** [What choice needs to be made]
**Stakes:** [Why this matters]
**Constraints:** [Time, resources, reversibility]
**Current thinking:** [What you believe now]
```

### Step 2: Select Relevant Models

Choose 3-5 models from different disciplines:

| Discipline | Example Models |
|------------|---------------|
| **Economics** | Opportunity cost, incentives, supply/demand |
| **Psychology** | Confirmation bias, loss aversion, social proof |
| **Systems** | Feedback loops, emergence, second-order effects |
| **Biology** | Evolution, natural selection, ecosystems |
| **Physics** | Inertia, leverage, critical mass |
| **Mathematics** | Probability, compounding, regression to mean |

```markdown
## Model Selection

| Model | Discipline | Why Relevant |
|-------|------------|--------------|
| [Model 1] | [Discipline] | [How it applies] |
| [Model 2] | [Discipline] | [How it applies] |
| [Model 3] | [Discipline] | [How it applies] |
```

### Step 3: Apply Each Model

Analyze the problem through each lens:

```markdown
## Model Analysis: [Model Name]

**Model definition:** [One sentence explanation]

**Applied to this problem:**
- [Insight 1]
- [Insight 2]

**What this model suggests:**
[Recommendation from this lens]

**Model limitations here:**
[Where this model might mislead]
```

### Step 4: Find Convergence and Divergence

Look for agreement and disagreement across models:

```markdown
## Model Synthesis

### Where Models Agree
- [Convergent insight 1]: Models [X, Y, Z] all point to this
- [Convergent insight 2]: Models [A, B] suggest this

### Where Models Conflict
- [Model X] suggests [action] but [Model Y] suggests [opposite]
- Reason for conflict: [Why they disagree]
- Resolution: [How to reconcile or choose]

### Highest-Confidence Insights
| Insight | Supporting Models | Confidence |
|---------|-------------------|------------|
| [Insight] | [Model list] | High/Medium |
```

### Step 5: Generate Recommendations

Synthesize into actionable guidance:

```markdown
## Recommendations

### Primary Recommendation
[What to do, informed by multiple models]

### Key Considerations
- From [Model A]: [Consideration]
- From [Model B]: [Consideration]

### Watch Out For
- [Risk 1]: [Which model highlights this]
- [Risk 2]: [Which model highlights this]
```

## Core Mental Models Reference

### Economics Models

| Model | Definition | When to Apply |
|-------|------------|---------------|
| **Opportunity cost** | True cost = what you give up | Resource allocation decisions |
| **Incentives** | People respond to rewards/punishments | Designing systems, understanding behavior |
| **Supply/demand** | Price balances availability and desire | Market dynamics, pricing |
| **Comparative advantage** | Focus on relative strengths | Partnership, hiring, outsourcing |
| **Marginal thinking** | Evaluate next unit, not average | Scaling decisions |
| **Sunk cost** | Past costs shouldn't affect future | Continuing vs stopping |

### Psychology Models

| Model | Definition | When to Apply |
|-------|------------|---------------|
| **Confirmation bias** | Seeking evidence for existing beliefs | Evaluating decisions, research design |
| **Loss aversion** | Losses feel 2x worse than gains | Pricing, change management |
| **Social proof** | Copying others' behavior | Marketing, adoption strategies |
| **Availability heuristic** | Overweighting recent/vivid info | Risk assessment |
| **Anchoring** | First number influences judgment | Negotiation, pricing |
| **Status quo bias** | Preferring current state | Change initiatives |

### Systems Models

| Model | Definition | When to Apply |
|-------|------------|---------------|
| **Feedback loops** | Outputs become inputs | Understanding dynamics |
| **Emergence** | Wholes have properties parts lack | Complex systems |
| **Second-order effects** | Consequences of consequences | Policy, strategy |
| **Bottlenecks** | Constraint limits whole system | Process optimization |
| **Network effects** | Value increases with users | Platform strategy |
| **Antifragility** | Gains from disorder | Risk design |

### Biology Models

| Model | Definition | When to Apply |
|-------|------------|---------------|
| **Natural selection** | Fit survive, unfit don't | Competition, market dynamics |
| **Adaptation** | Organisms change to fit environment | Strategy response |
| **Red Queen effect** | Must run to stay in place | Competitive markets |
| **Ecosystem** | Interconnected community | Partnership, platforms |
| **Evolution** | Gradual change through variation | Product development |

### Physics Models

| Model | Definition | When to Apply |
|-------|------------|---------------|
| **Inertia** | Objects resist change in motion | Change management |
| **Leverage** | Small force, big effect | Finding high-impact actions |
| **Critical mass** | Threshold for chain reaction | Adoption, virality |
| **Entropy** | Systems tend toward disorder | Maintenance, organization |
| **Conservation of energy** | Can't create from nothing | Resource planning |

### Mathematics Models

| Model | Definition | When to Apply |
|-------|------------|---------------|
| **Compounding** | Growth on growth | Investment, learning, debt |
| **Probability** | Likelihood of outcomes | Decision under uncertainty |
| **Regression to mean** | Extremes tend toward average | Performance evaluation |
| **Power laws** | Few dominate many | Market structure |
| **Pareto principle** | 80% from 20% | Prioritization |

## Examples

**Output: Multi-Model Analysis**

```markdown
# Mental Models Analysis: Whether to Expand to Enterprise Market

## Problem Statement
**Situation:** We're a successful SMB SaaS company considering moving upmarket to enterprise
**Decision:** Should we invest in enterprise sales and product capabilities?
**Stakes:** $2M investment, 18-month timeline, could transform or sink the company
**Constraints:** Limited capital, current team is SMB-focused, competitors already there
**Current thinking:** Enterprise = bigger deals = more revenue, seems obvious

---

## Model Selection

| Model | Discipline | Why Relevant |
|-------|------------|--------------|
| Opportunity cost | Economics | What do we give up by going enterprise? |
| Comparative advantage | Economics | Where do we actually win? |
| Feedback loops | Systems | How does this change company dynamics? |
| Inertia | Physics | How hard is the organizational change? |
| Loss aversion | Psychology | Why does enterprise feel "safer"? |

---

## Model Analysis

### Model 1: Opportunity Cost (Economics)

**Applied to this problem:**
- Enterprise investment means NOT investing in SMB growth, new product features, or operational efficiency
- $2M and 18 months of focus has significant alternative uses
- Enterprise sales cycles (6-12 months) mean cash tied up longer

**What this model suggests:**
Compare enterprise ROI to alternative investments explicitly. The question isn't "is enterprise good?" but "is enterprise BETTER than alternatives?"

**Model limitations:**
Doesn't account for strategic positioning or learning from enterprise customers.

---

### Model 2: Comparative Advantage (Economics)

**Applied to this problem:**
- Our advantage is speed, simplicity, and self-serve onboarding
- Enterprise wants customization, integrations, and white-glove service
- Our DNA is opposite of enterprise requirements
- Competitors have 5+ years of enterprise experience

**What this model suggests:**
We'd be competing where we're weakest against entrenched players. Better to dominate SMB than struggle in enterprise.

**Model limitations:**
Advantages can be built; this is a snapshot, not destiny.

---

### Model 3: Feedback Loops (Systems)

**Applied to this problem:**
- Enterprise deals create pressure for more enterprise features
- Enterprise features make SMB product more complex
- Complexity drives up support costs and slows development
- Slower development makes us less competitive in SMB
- Less competitive SMB = declining revenue = more pressure to chase enterprise

**Potential negative loop identified:**
Enterprise → Complexity → SMB decline → More enterprise dependence

**What this model suggests:**
Enterprise isn't a parallel track — it feeds back into core business. Must plan for system-wide effects.

**Model limitations:**
Loops can be managed with discipline; doesn't mean they're inevitable.

---

### Model 4: Inertia (Physics)

**Applied to this problem:**
- Team is in motion toward SMB velocity
- Enterprise requires complete sales process change
- Product roadmap must shift direction
- Culture must change (long cycles vs quick wins)
- Organizations resist this much change

**What this model suggests:**
The transition will take MORE effort than expected because we're not starting from rest — we're reversing direction.

**Model limitations:**
Inertia can be overcome with sufficient force; doesn't say "never change."

---

### Model 5: Loss Aversion (Psychology)

**Applied to this problem:**
- Enterprise feels "safer" because deals are bigger (fewer to lose)
- We're anchoring on enterprise success stories, ignoring failures
- Fear of missing out on "real" revenue is driving decision
- Current SMB churn feels like "losing" even if normal

**What this model suggests:**
Question whether enterprise desire is strategic or emotional. Are we running toward enterprise or away from SMB anxiety?

**Model limitations:**
Sometimes fear is informative; loss aversion isn't always wrong.

---

## Model Synthesis

### Where Models Agree (High Confidence)
1. **Hidden costs are high:** Opportunity cost, feedback loops, and inertia all point to underestimated investment
2. **DNA mismatch:** Comparative advantage strongly suggests we're not positioned for enterprise
3. **Emotional drivers:** Loss aversion reveals this may be reactive, not strategic

### Where Models Conflict
- **Opportunity cost** asks "compared to what?" but we haven't modeled alternatives
- **Comparative advantage** is static; we COULD build enterprise capability

### Highest-Confidence Insights

| Insight | Supporting Models | Confidence |
|---------|-------------------|------------|
| We're underestimating transition cost | Opportunity cost, inertia | High |
| Enterprise will cannibalize SMB focus | Feedback loops | High |
| Decision may be emotionally driven | Loss aversion | Medium |
| We're not positioned to win enterprise | Comparative advantage | Medium |

---

## Recommendations

### Primary Recommendation
**Don't pursue enterprise now.** Multiple models converge on hidden costs and positioning disadvantage.

### Alternative Path
Instead of enterprise, invest $2M in:
1. **SMB expansion:** New markets where our comparative advantage applies
2. **SMB retention:** Reduce churn that's triggering loss aversion
3. **Product moat:** Features that make SMB defense stronger

### Key Considerations
- From **Opportunity Cost:** Model alternative uses of $2M before deciding
- From **Feedback Loops:** If enterprise ever, firewall it completely from SMB team

### Watch Out For
- **Confirmation bias:** We might seek evidence enterprise is bad because we're afraid
- **Competitor moves:** If enterprise competitors move down to SMB, calculus changes
- **Investor pressure:** Enterprise story is better for fundraising; be honest about motivation

### When to Reconsider
- SMB market saturates
- We've built enterprise-ready product naturally
- Competitor acquisition creates gap
```



## Quality Tests

### Evidence Test
- Strategy is grounded in data and observations, not assumptions
- **PASS:** Each strategic recommendation traces to specific evidence
- **FAIL:** Strategy based on intuition without supporting data

### Completeness Test
- All relevant forces and stakeholders have been considered
- **PASS:** Analysis covers internal, external, and competitive dynamics
- **FAIL:** Only internal factors considered, external forces ignored

## Guidelines

1. **Use 3-5 models** — Enough for triangulation, not so many it's overwhelming
2. **Pick from different disciplines** — Avoid models that are secretly the same
3. **Apply honestly** — Models should challenge, not confirm
4. **Note limitations** — Every model has blindspots
5. **Seek convergence** — Multiple models agreeing = higher confidence
6. **Embrace conflict** — Disagreement reveals complexity

## Anti-Patterns

| Anti-Pattern | Problem | Better Approach |
|--------------|---------|-----------------|
| Single-model thinking | Blindspots | Always use multiple models |
| Confirmation fit | Choosing models that agree with you | Pick models that might disagree |
| Model worship | Treating model as truth | Models are lenses, not reality |
| Analysis paralysis | Too many models, no decision | Cap at 5, synthesize, decide |
| Surface application | Mentioning model without applying | Deep application with specifics |
